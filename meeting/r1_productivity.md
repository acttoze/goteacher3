# R1 제안서 — 업무 생산성·협업툴 관점

## 1. 오브젝트 모델: 학교 일은 다섯 가지뿐이다
쪽지 한 통에는 대개 "언제(일정)·무엇을 내라(요청)·알아둬라(공지)"가 섞여 있다. 이걸 쪼개서 각각을 상태와 소유자가 있는 카드로 만든다.

| 오브젝트 | 상태 전이 | 소유자 |
|---|---|---|
| 일정 | 예정→변경→종료 | 등록자(복무는 본인) |
| 요청(취합) | 초안→배포→수합 중→마감→합본 완료 | 담당 계원 |
| 공지 | 게시→개정(v2…)→보관 | 발신 부서 |
| 할일 | 받음→완료 (요청을 받으면 자동 생성) | 받는 교사 |
| 문서 | 양식/결과물, 버전 보관 | 업무분장상 부서 |

원칙은 "받은 사람 쪽에는 할일 하나만 남긴다"이다. Linear 이슈처럼 마감·담당·상태를 모두 갖추되, 교사 화면에는 "오늘 낼 것 3건"만 보이게 한다. DB를 보면 제목의 14%가 `이름|출장(시간,장소)` 형식이다. 교시·장소·대상·복무유형은 자유 텍스트로 받지 말고 필드로 받는다.

## 2. 취합 워크플로우
1. **양식 변환**: hwp 표를 복사해서 붙여넣으면 열 머리글이 웹폼 필드가 된다. 학급별 행을 미리 채운 "내 칸만 채우기" 방식이며 셀 단위 제출이라 잠금이 필요 없다.
2. **배포**: 대상은 학년·부서·업무분장에서 고르고, 쿨메신저에 붙일 링크를 자동으로 만든다.
3. **개별 제출**: 로그인 없이 학교 인증 링크로 연다. 모바일에서 30초 안에 끝나야 한다.
4. **자동 합본**: 실시간 표를 보여 주고, 원본 hwp 양식 그대로 xlsx·hwpx로 내보낸다. 이 단계가 고시트에 없던 핵심이다.
5. **리마인드**: 미제출자 명단을 누르면 바로 쪽지 문구가 복사된다. D-1과 당일 아침 8시(작성 피크 시간)에 자동 알림을 보낸다.
6. **마감**: 잠근 뒤 늦은 제출은 "지각" 표시와 함께 받는다.

## 3. 공지 변경 전파
- 수정할 때마다 v2, v3로 버전을 올리고 diff 하이라이트를 붙인다("장소: 강당→체육관").
- 실질 변경(일시·장소·제출물)이면 이전 확인자에게 **재확인(ack)**을 요청하고, 오탈자 수정은 조용히 반영한다.
- 확인 현황은 "28/32, 미확인 4명"처럼 보여 주고 리마인드 버튼과 연결한다. 연결된 일정과 할일도 같이 갱신된다.

## 4. 메신저는 대체하지 않고 흡수한다
쿨메신저 점유율은 약 70%이고 이 습관은 바뀌지 않는다. 그래서 메신저를 **알림 채널**로 쓰고 티로드를 **기록 원장**으로 둔다.
- 쪽지 붙여넣기 → 날짜·마감·대상 자동 추출 → 일정/요청/공지 카드로 변환해 제안(사람이 확인한 뒤 저장)
- 카드마다 짧은 링크와 메신저용 문구를 자동으로 만든다(로그인 없이 보기와 확인 1클릭)
- 메신저 쪽에는 "링크만 오가고 원본은 한 곳에 있는" 상태를 만든다

## 5. 고티처 대비 구조적 우위 / 과설계 경고
**우위**
1. 일정만 다루는 캘린더가 아니라 요청→할일→합본으로 **닫히는 루프**가 있다. 일을 끝내 주는 도구다.
2. 링크 기반 비로그인 참여 덕분에, 1명만 가입한 학교에서도 전원이 쓸 수 있다(고티처 117곳 중 49곳이 회원 1명).
3. 공지 버전 관리와 재확인으로 "바뀐 걸 몰랐다"는 일이 사라진다. 고티처 평균 조회 1.73회의 원인을 푼다.

**경고**
1. 칸반·프로젝트·하위작업·태그 같은 노션/아사나식 범용 구조는 쓰지 않는다. 교사는 분류하지 않는다.
2. 댓글·채팅·스레드는 넣지 않는다. 고티처 댓글 0.6%가 보여 주듯 대화는 메신저에 맡긴다.
3. 결재와 공문 연동은 에듀파인 영역이다. 흉내 내면 법적·보안 부담만 커진다. 개인 GTD식 우선순위·컨텍스트 설정도 하지 않는다.
