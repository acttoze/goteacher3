### 1-2. MVP에서 빼는 것

- 블록 끌기·카드 기간 끌기 → v1(보기와 ＋추가만)
- A3 인쇄, 한글 양식의 □체크·( )·날짜·서명 자리, 한 양식에서 여러 표 동시 취합 → v1
- 돌아온 hwp 여러 개에서 표 값 모으기(역방향 취합) → v1 첫 후보(읽기 성공률 100%라 위험이 낮음)
- 쪽지 붙여넣기 AI 변환, 반복 일정, 업무분장 연도 인수인계 → v1
- 문자 인증, 사람별 링크(결정으로 제외), 중·고등학교(7교시·석식), PC 에이전트 → v2 이후

### 1-3. 범위 판단 기준

생산성 검토의 콜드 스타트 지적을 따른다. **첫날 한 사람만 써도 가치가 나는 것(모으기·한글 채우기·급식 TV)을 먼저 완성**하고, 여러 사람이 입력해야 살아나는 화면(오늘·공지·학교)은 그다음에 만든다.

### 2-1. 인증과 "PC 기억"

- 교직원: 학교 초대 링크·QR → 이름·그룹·직책을 고르면 **긴 수명의 기기 토큰(1년)** 을 쿠키와 localStorage 두 곳에 저장한다.
- 복원 프로그램이 걸린 PC에서 토큰이 사라지면, 다음 쪽지 링크를 열 때 "누구신가요?"로 다시 고르면 된다. 비밀번호와 문자는 쓰지 않는다.
- 받는 사람 제출(`/c/{토큰}`)은 로그인 없이 연다. 대리 제출을 허용하고, '내는 사람'과 IP 대역·시각을 기록한다.
- 관리자(교감·교무부장) 권한은 학교 안에서 지정한다. 업체 계정은 정보부장이 휴대폰 번호로 초대하고, 문자 인증은 업체에만 쓴다.

## 3. 핵심 설계

### 3-1. 데이터 모델 (요지)

```
School(neis_atpt, neis_code, name, plan) ─┬─ Member(name, group, position, device_tokens)
                                          ├─ Group / Duty(부서·업무분장, 학년도)
                                          ├─ Event(date, end, slot_from/to, target, type, by, changed_from)
                                          ├─ Attendance(date, member, kind[출장·외출·조퇴·연가·휴가·지각], time)  ← 사유 칸 없음
                                          ├─ Collection(title, source[paste|sheet|preset|hwp], due, aud, fields[], pii_fields[], footer_on)
                                          │    ├─ Row(unit, who, gid) ── Cell(field, value | ciphertext, by, at)
                                          │    └─ SourceFile(원본 hwp/hwpx, 표 위치, 칸 매핑 JSON) → ResultFile
                                          ├─ Notice(versions[], must, real) ── Ack(member, version, at)
                                          ├─ Repair(cat[시설|정보], place, status, reply) / VendorAccount(phone, until)
                                          └─ MealSettings(order, sec, off, hygiene) / MealPhoto(date, file, at)
Vendor(cat, area) ── VendorReview(badges[], line≤40, by_area, at)      FormLibrary(운영자 등록)
```

### 3-2. 한글 양식 채워 받기 흐름

1. 업로드: 매직 바이트로 판별한다(`PK`=hwpx, `D0CF11E0`=hwp). hwp는 서버에서 HWPX로 변환하고, 변환 보고에 빠진 요소가 있으면 알린다.
2. 브라우저에서 rhwp로 미리보기를 띄우고 표 후보를 점수순으로 강조한다. **교사가 한 번 눌러 확정**한다(자동 1순위 적중률 약 70%).
3. 칸 확인: 자동으로 만든 라벨을 다듬고, 입력 칸을 켜고 끄고, 행 머리(반·이름)를 배정한다. 합계 행은 뺀다.
4. 링크로 걷기(기존 모으기와 같음) → 칸 주소(표·행·열) 단위로 병합하고 충돌을 경고한다.
5. 내려받기: 서버 큐가 python-hwpx `fill_cells`(+행 추가)를 돌린다. 올린 형식 그대로 주고 hwpx도 함께 준다. 쪽수가 늘면 "글자 줄이기" 옵션을 띄운다.
6. **학생 칸이 있으면** 서버는 그 칸을 비운 파일을 만들고, 요청자 브라우저가 rhwp로 학생 값을 채워 저장한다(3-3).

### 3-3. 학생 정보 비저장 — 설계안

- 모으기를 만들 때 요청자 브라우저가 키 쌍(WebCrypto ECDH P-256)을 만든다. 공개키는 서버에 두고, **개인키는 요청자 기기와 '관리 링크'의 # 뒤 부분에만** 둔다(서버로 전송되지 않음).
- 받는 사람 브라우저는 학생 칸 값을 공개키로 암호화해 보낸다. 서버는 암호문만 저장하므로 **티로드도 읽을 수 없다.**
- 요청자가 합본을 열면 브라우저에서 복호화해 보여 주고, 엑셀·한글 파일은 브라우저에서 만든다(SheetJS 대신 CSV / rhwp로 hwp).
- 내려받기를 마치거나 마감 후 30일이 지나면 서버의 암호문을 지운다. 티로드에는 제출 여부와 인원 수만 남긴다.
- **위험:** 요청자 PC가 복원되고 관리 링크도 없으면 학생 값을 영영 못 연다. 그래서 만들 때 "관리 링크를 쪽지함에 보관하세요" 안내와 '나에게 보내기' 문구를 띄운다. 이 위험은 파일럿에서 실제로 측정한다.
- 법률 검토가 필요한 점(개인정보 보호법 제26조 위탁 해당 여부)은 '암호문만 보관'이 위탁에 해당하는지 출시 전에 자문을 받는다.

### 3-4. 급식 현황판

- 프로토타입 `assets/meal.js`를 서버 모듈로 옮긴다(NEIS 파싱·식품군 규칙·위생 순환·표준 영양 기준).
- TV는 학교별 공개 URL(추측하기 어려운 토큰), 영양사 입력은 교직원 로그인이 필요하다. 폰 QR 링크에는 그날만 유효한 업로드 토큰을 넣는다.
- 사진이 없을 때는 메뉴로 대체하고, NEIS가 끊기면 저장본으로 돌린다.

## 6. 품질·보안 기준

- 고티처의 교훈을 그대로 금지한다. 권한 검사 누락, PIN 평문 저장, SQL 문자열 결합.
- 모든 조회에 `school_id` 필터를 두고, **다른 학교 데이터 접근 테스트**를 CI에 넣는다.
- 업로드는 신뢰하지 않는다. 매직 바이트 판별, 크기 제한, lxml 엔티티 해석 끔, zip 폭탄 가드, 작업당 시간·메모리 제한을 둔다.
- 한글 회귀 테스트: `research/hwp_poc`의 벤치 스크립트로 양식 표본 100개를 매 배포마다 다시 채워 검사한다.
- 화면 기준(확정 원칙): PC 1440~1920px, 본문 16px·보조 15px·버튼 40px 이상, 125% 배율 1536×750에서 첫 화면 확인. 폰은 `meal-photo` 하나뿐이다.
- 로그: 제출·확인·업체 접속 기록을 보관한다. 학생 값과 복무 사유는 로그에도 남기지 않는다.

## 8. 성공 지표 (파일럿 → 출시 12주)

1. 첫 제출 전환: 링크를 연 사람의 80% 이상이 48시간 안에 제출, 제출 시간 중앙값 60초 이하
2. 두 번째 발신자: 첫 발신 뒤 30일 안에 다른 교사가 모으기를 만든 학교 40% 이상
3. 재방문: 4주차에 제출이 아닌 목적으로 '오늘'을 연 교사 30% 이상
4. 한글 채워 받기 성공률: 올린 양식 중 사람 확인 한 번으로 내려받기까지 간 비율 85% 이상
5. 급식 TV 가동: 파일럿 학교 TV 하루 가동률 99%, 식판 사진 당일 게시율 90% 이상

## 9. 사용자가 정할 것

1. **'원본 한글 양식에 채워 받기'의 무료·유료 경계**: 기존 수익 모델에서는 학교 플랜(유료) 기능이었다. 바이럴의 핵심이라 무료로 열 필요가 있다. 안: 무료는 월 N건, 학교 플랜은 무제한.
2. **파일럿 학교**: 김해봉황초 외 2~4곳(교육청 2곳 이상). 섭외는 사용자가 한다.
3. **호스팅**: 공공 클라우드(CSAP 대응) vs 일반 클라우드로 시작해 나중에 옮기기.
4. **학생 정보 잠금의 복구 수단**: 개인키를 관리 링크로만 둘지, 학교 복구 키(교감 보관)를 둘지.
5. **출시일**: 2/15(새 학년 준비 기간 시작) 고정 여부.
