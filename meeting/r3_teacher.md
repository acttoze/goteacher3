# R3 — 현장 현실성 검토 (4학년 담임, 받는 쪽)

## 1. 화면별 판정
| 화면 | 판정 | 근거(장면) |
|---|---|---|
| 오늘 | 수정 | 노랑 '바뀐 것'은 매일 열 이유가 됨. 그런데 4-2 담임에게 3학년 수영 출발시각과 2학년 연가가 뜸. 남의 변경이 섞이면 사흘 뒤엔 안 읽음 |
| 일정(주간·월간) | 유지 | 보기·인쇄용. 담임이 넣는 일은 드묾. 교무부장의 '주간계획 붙여넣기'에 달림 |
| 모으기 만들기 | 수정 | 숫자형은 좋음. 현장 취합의 절반은 학생 명단인데, 학생 개인정보 비저장 원칙 때문에 명단형을 못 만듦 |
| 받는 사람 제출 | 유지 | 칸 3개 → 제출하기, hwp를 안 열어도 됨. 단 '누구신가요?'에서 명부 아무 이름이나 고를 수 있음(사칭 가능) |
| 합본 | 유지 | 미제출 칩, 독촉 문구 복사, 한글에 붙여넣기. 학년대표 일이 30분에서 3분으로 줆 |
| 게시판 공지 판 관리 | 수정 | v2와 바뀐 부분(diff)은 좋음. 공지는 쪽지로도 오니 볼 곳이 둘이 됨. '오늘'에 녹여야 함 |
| 공지 확인 | 수정 | '내 확인 전' 빨간 배지와 31/38, 재확인 19명 표시가 점검받는 느낌을 줌 |
| 학교·복무 | 수정 | 나이스에서 결재받고 여기에 또 입력하는 이중 일. '병원', '개인' 같은 사유가 전 직원에게 보임 |
| 학교·분장 | 유지 | 2월에 한 번 보고, 1년 내내 '이 업무 누구지?' 찾는 용도 |
| 한 줄 입력 | 유지(비핵심) | 담임은 일주일에 1~2번 씀. |
| 교외·양식 자료실 | 유지 | 로그인 없이 검색해서 들어오는 길 |
| 교외·협력업체 | 보류 | 별점은 청렴·특정 업체 홍보 시비가 남. 계약은 행정실 일 |
| 교외·정보 수리 | 수정 | 교육청 통합유지보수 접수 창구가 있는 지역은 이중 접수. |
| 새 학년 세팅 | 유지 | 이름, 그룹, 직책만 고르면 됨. 다만 기간제는 3월에 들어옴 |
| 급식 현황판 | 유지 | 담임 입력 0. 줄 선 아이들이 알레르기 번호를 봄. |
| 영양사 입력 | 수정 | 식판 사진은 이미 홈페이지 식단 게시판에 올림. 매일 '필수'로 두면 이중 일 |

## 2. 담임이 매일 해야 하는 입력
- 모으기 제출(쪽지 링크 → 칸 채우기) — **함.** hwp 회신보다 빠름
- 공지 열람 — **함.** 열어 보는 것만으로 확인 처리되는 동안만
- 내 시간표(학기 초 1회) — **처음만 함.** 전담 교체나 행사 주간에 생기는 수정은 안 함
- 복무 공유(출장·조퇴) — **안 함.** 나이스 결재와 이중
- 일정 블록 끌기, 기간 늘리기 — **안 함.** 내가 쓴 일정도 아닌데 시간까지 맞출 이유가 없음
- "제 것이 아니에요" 누르기 — **안 함.** 그냥 무시함
- 수리요청 — 가끔. 지금도 정보부장에게 쪽지 한 줄이면 끝남

## 3. 현장에서 막히는 지점 Top 5
1. **망분리와 외부 사이트 차단.** 쿨메신저 링크를 업무망 PC 브라우저에서 열면 외부 도메인이 막히는 교육청이 있음. 보안성 검토와 화이트리스트 등록을 누가 신청할지 정해지지 않음
2. **학생 명단 취합을 못 함.** 체험학습, 방과후, 돌봄처럼 명단이 필요한 취합이 빠지면 바이럴 엔진의 연료가 절반 사라짐
3. **위에서 안 쓰면 확인할 곳만 늘어남.** 교무부장과 교감이 계속 hwp를 첨부해 쪽지를 보내면 담임은 쪽지와 티로드 둘 다 봐야 함(고티처 실패 이유 그대로)
4. **'PC 1년 기억'이 깨짐.** 복원 프로그램, 브라우저 정리, 공용 PC(교무실·특별실) 때문. 개인 휴대폰 번호로 문자 인증하는 것도 꺼리는 교사가 있음
5. **결제와 승인.** 연 29~49만 원은 품의, 학교장터 등록, 정보보호 검토를 거쳐야 함. 관리자가 "개인정보 괜찮아요?" 한마디 하면 거기서 멈춤

## 4. 설득력
**동학년에 권할 장면**
1. 현장체험 합본: 8반 중 6반 제출, 미제출 칩을 누르면 독촉 문구가 복사되고, 합본 표를 한글에 붙여넣음
2. 링크를 열면 우리 반 칸 3개만 보임. 30초면 제출하고 다른 반 값은 안 보임
3. '오늘 바뀐 것': ~~강당~~ → 체육관, ~~2블록~~ → 3블록. 수정본 hwp 세 개를 비교할 필요가 없어짐

**반감 살 요소**
1. 확인 현황(31/38, 재확인 19명)과 미확인자 명단: 점검받는 느낌
2. 복무 사유와 동료 연가가 '바뀐 것'으로 노출됨
3. 교육청에 내는 합본에 "티로드로 모았습니다" 꼬리말: 결재권자 눈에 광고로 보임. 블록, 전일, 그룹·부서, 교내/교외 같은 새 용어도 부담

## 5. 구현 계획 전에 고칠 것 (우선순위)
1. **학교 PC 실측:** 교육청 2~3곳의 업무망 PC에서 쿨메신저 링크가 열리는지, 로그인이 유지되는지, 복원 프로그램이 있는지 확인.
2. **학생 정보 원칙 재설계:** 명단 열을 허용하고 마감 30일 뒤 자동 파기 같은 방식. 아니면 명단형 취합을 포기한다고 명시
3. **복무 축소:** 사유 칸을 없애고 입력자를 1명(교무실무사)으로 지정. 그게 안 되면 복무 기능을 뺌
4. **받는 사람 신원:** 명부 선택에 문자 인증을 붙인 흐름을 프로토타입에 반영하고, 공용 PC 대안 마련
5. **노출 줄이기:** '오늘 바뀐 것'은 나·우리 학년·전 교직원 대상만 보이게, 확인 현황은 보낸 사람에게만 비율로, 합본 꼬리말은 끌 수 있게
