# 2차 피드백 검토·반영 기록 — 2026-10-27

v1.1 프로토타입에 대한 2차 피드백, 검토 결과, v1.2 반영 위치. 가장 중요한 항목은 **1. 오늘 — 누가 입력하나**.

---

## 1. 오늘 — 누가 입력하나 (가장 중요)

### 1-1. 문제
'오늘' 화면의 가치는 데이터가 얼마나 빠짐없이 들어와 있느냐에 달려 있다. 교시까지 나눠 보여 주려면 결국 누군가 교시까지 입력해야 한다. 내 시간표는 학기 초에 내가 한 번 넣으면 되지만, 학교 일정 전부를 누가 교시 단위로 넣느냐가 문제다.

근거:
- 고티처는 처음부터 **날짜만** 받았다(`wr_1/2` 시작·종료일, 시간 필드 없음 — research/03). 그런데도 제목의 38%에 시간을 직접 적었다(research/01). 시간이 필요한 사람은 있었지만, 필수 입력으로 만들었다면 102,579건이 쌓이지 않았을 가능성이 높다.
- 활성 교사가 학교당 2.9명뿐이었다. 입력 부담이 늘면 '일기장' 구조는 더 굳어진다.

### 1-2. 일정 종류별로 따져 보기

| 일정 종류 | 지금 어디서 오나 | 티로드에서 누가 넣나 | 필요한 정밀도 | 추가 부담 |
|---|---|---|---|---|
| 학사일정·공휴일·급식 | NEIS | 자동 | 날짜 | 없음 |
| 주간교육계획 | 교무부장이 매주 한글·엑셀로 이미 만듦 | 교무부장이 **표를 붙여넣기** 1회 | 시간 칸이 있으면 교시, 없으면 전일 | 주 1회 붙여넣기 |
| 부서 행사·교육 안내 | 담당자가 쿨메신저 쪽지로 보냄 | 담당자가 한 줄 입력(쪽지 쓰는 김에) | 날짜 기본, 쪽지에 교시를 썼으면 교시 | 쪽지 문구가 자동으로 나오므로 상쇄 |
| 내 시간표 | 학기 초 시간표 | 본인 1회 | 교시 | 학기 1회 |
| 특별실 사용 | 종이 예약표·구두 | 쓰는 사람 | **교시 필수** | 예약이 목적이라 입력 동기 있음 |
| 복무(출장·조퇴) | 나이스 결재 | 공유하고 싶은 사람만 | 날짜(+시각) | 선택 |
| 모으기 마감·공지 일시 | 티로드 안 | 자동 | 시각 | 없음 |

정리하면 **교시가 정말 필요한 건 내 시간표·특별실·수업과 겹치는 행사 정도**다. 나머지는 날짜만으로 충분하거나, 교시를 아는 사람(담당자·같은 학년)이 따로 있다.

### 1-3. 결정: "날짜는 필수, 시간은 선택 — 필요한 사람이 끌어서 정한다"
1. **기본 입력은 날짜만**(고티처와 같은 부담). 날짜만 넣은 일정은 '오늘'과 '일정' 맨 위 **전일** 칸에 모인다.
2. **시간은 끌어서 정한다**(피드백에서 제안한 방식 채택).
   - 전일 카드를 교시 줄에 끌어다 놓으면 그 교시가 된다.
   - 카드의 **위·아래 끝을 끌면** 교시 단위로 길이가 바뀐다.
   - 빈 교시 줄을 두 번 누르면 그 교시에 카드가 생긴다.
   - 교시 카드를 전일로 끌어 올리면 다시 '시간 미정'이 된다.
3. **누가 끌 수 있나** = 쓴 사람 + 쓴 사람과 같은 그룹(4학년 일정은 4학년 선생님 누구나). 정밀하게 맞추는 일을 그 일정에 관심 있는 사람들에게 나눈다.
4. **한 줄 입력에 "3~4교시"를 쓰면** 처음부터 교시로 들어간다. 안 쓰면 전일로 간다(v1.1은 자동으로 '방과후'로 넣었는데, 이를 없앰).
5. **이미 정해진 시간을 바꾸면** 관련 선생님의 '오늘 바뀐 것'에 뜬다. 시간 미정이던 일정에 처음 시간을 정하는 건 알리지 않는다(알림 소음 방지).
6. **주간교육계획 표 붙여넣기**: 교무부장이 이미 만드는 표(날짜·시간·내용·장소·담당)를 붙여넣으면 한 주 일정이 한꺼번에 들어간다. 시간 칸이 비면 전일로, 담당 칸의 이름이 명부에 있으면 그 선생님 이름으로 등록한다. 입력 문제에서 효과가 가장 클 것으로 본다.

### 1-4. 드래그 방식 평가
- **좋은 점**: 숫자를 입력하지 않는다. 시간표와 같은 시각 언어를 쓴다. 교시 단위로 딱 맞춰지니(스냅) 어긋날 일이 적다. PC 전용 환경이라 마우스 전제가 맞다.
- **위험**:
  - 50대 교사의 마우스 정밀도 → 위아래 손잡이를 넉넉하게 만들고(카드 끝 12px), 끄는 동안 "3~4교시" 말풍선과 놓일 자리 점선 미리보기를 보여 준다.
  - 남의 일정을 실수로 옮김 → 권한(쓴 사람·같은 그룹)과 '바뀐 것' 알림으로 막는다. 되돌리기(Ctrl+Z)는 v1.
- **대안 경로도 둔다**: 카드를 누르면 '시간 미정' 체크와 시작·끝 교시 선택이 있다. 드래그가 어려운 분도 같은 일을 할 수 있다.

### 1-5. 검증해야 할 것 (다음 단계)
- 실제 학교 1곳의 2주치 일정에서 교시가 실제로 중요한 일정의 비율 측정. 가설은 30% 미만.
- 교무부장 주간계획 표 양식을 5개 학교에서 모아 붙여넣기 파서 검증(칸 순서·병합 셀·요일 표기).
- 드래그 사용성 테스트: 50대 교사 3명, 과제 "전일의 '학년협의'를 5~6교시로".
- 운영 지표: 전일 비율, 끌어서 시간을 정한 횟수, 주간계획 붙여넣기 사용 학교 수.

## 2. 일정

| 피드백 | 결정 (v1.2) |
|---|---|
| 아이콘 필요 없고 색으로만 구분, 단 최근 변경은 아이콘 | 유형 기호(◆■▲○)를 화면에서 뺌 → 유형은 **8px 색 점**. 최근 변경은 **↻ 아이콘**(노랑 테두리 함께). 기호는 흑백 인쇄에서만 나옴 |
| 최상단에 '전일 칸' | 주간·오늘 모두 맨 위에 **전일**(시간 미정·종일). 1~6교시를 다 쓰는 일정도 전일로 감 |
| 시간대가 너무 자세함, 4시간대와 그 이름 | 주간은 교시 대신 **4블록** — 아래 참고 |
| 카드 디자인, 왼쪽 색띠 | 색띠 삭제. **흰 카드 + 얇은 테두리 + 색 점** |
| 카드가 모두 색을 가질 필요가 있나 | 아래 의견 |

### 2-1. 시간대 이름: '블록'
오전 반·반, 오후 반·반으로 나누면 초등 시정표에서 자연스럽게 아래처럼 나뉜다. 이 묶음을 학교에서는 이미 **블록**이라고 부른다(블록수업 = 2교시를 80분으로 묶는 수업). 그래서 티로드만의 새 이름은 만들지 않았다. 새 말은 선생님들이 따로 익혀야 하기 때문이다.

| 이름 | 범위 | 시각(시연 시정표) | 오전·오후 |
|---|---|---|---|
| 1블록 | 아침 · 1·2교시 | 08:40~10:30 | 오전 앞 |
| 2블록 | 중간놀이 · 3·4교시 | 10:30~12:20 | 오전 뒤 |
| 3블록 | 점심 · 5·6교시 | 12:20~14:40 | 오후 앞 |
| 방과후 | 14:40 이후 | 14:40~ | 오후 뒤 |

- 아침·중간놀이·점심은 바로 뒤 블록에 붙인다(아침 협의는 1블록, 점심 일정은 3블록).
- 교시까지 정한 일정은 그 블록 안에 "3~4교시"로 함께 표시한다. 시간대 칸은 거칠어도 정보는 잃지 않는다.
- **확인 필요**: 블록수업을 하지 않는 학교에서도 '1블록'이 통하는지 교사 3명에게 물어볼 것. 안 통하면 설정에서 '1·2교시 / 3·4교시 / 5·6교시 / 방과후'로 바꿀 수 있게 한다(시정표 붙여넣기 단계에서 고름).
- '오늘' 화면은 교시 축을 유지한다(내 시간표 옆에 놓이고, 드래그가 교시 단위로 맞춰져야 하므로). 왼쪽에 블록 이름을 함께 붙였다.

### 2-2. 카드 색에 대한 의견
**모든 카드가 색을 가질 필요는 없다.** 모든 카드에 색을 칠하면 색은 정보가 아니라 무늬가 된다. 주간 한 장에 30~40장이 뜨는 화면에서 네 가지 유형색이 고르게 깔리면, 정작 "내가 챙겨야 할 것"이 눈에 안 들어온다.

- **유형 색(행사·업무·회의)**: 제목 앞 **작은 점**으로만. 구분은 되지만 화면을 칠하지 않는다.
- **면 색**: 딱 하나, **나와 관련된 카드**에만 옅은 청록. 기준은 내가 쓴 것, 대상이 우리 반·우리 학년·담임·전 교직원인 것.
- **최근 변경**: 노란 테두리 + ↻ 아이콘.
- 월간은 면 대신 관련 항목만 **굵게 + 옅은 바탕**.
- 한계: '관련' 판정은 대상 칸의 글자에 기대므로, 그룹·대상 칩이 정확해야 잘 맞는다(한 줄 입력의 대상 칩이 이 역할).

## 3. 모으기

### 3-1. 양식 가져오기의 첫 번째 기본 = 직접 입력(시트)
- 구글 시트처럼 생긴 표에 **받을 항목 이름만** 적는다. A·B열(학년반·담임 또는 직위·성명)은 대상에 맞춰 자동이고, C열부터가 항목이다.
- 2행에서 형식(글자·숫자·선택지·날짜·링크)을 고른다. 선택지는 보기를 쉼표로 적는다.
- `Enter`를 누르면 열이 추가되고, ✕로 열을 지운다. 미리보기 행(1-1 강지은…)에서 받는 쪽 모습이 바로 보인다.
- **"받는 사람이 줄을 여러 개 추가"**를 켜면 여러 줄형이 된다(물품 신청처럼 한 반이 여러 줄). 숫자 열이 두 개 이상이면 금액(곱) 열이 자동으로 붙는다.
- 순서는 직접 입력(기본) → 자주 쓰는 양식 → 표 붙여넣기 → hwpx 올리기(v1).

### 3-2. 자주 쓰는 양식 — 누르면 바로 만들어짐
실제 학교 구글 시트 두 개를 분석했다. 스타일은 무시하고 항목과 방식만 옮겼으며, 실명은 옮기지 않았다.

| | 학습준비물 신청 | 교직원 연수 이수 현황 |
|---|---|---|
| 원본 시트 구조 | 학년별 탭 + 학년별 예산 현황 탭 + 구입 내역 탭 | 연수 목록 탭 + 연수마다 탭 하나(14개) |
| 항목 | 순·물품명·수량·단가·금액·학급(드롭다운)·링크 | 목록: 순·연수명·기간·대상·담당자·비고(연수 사이트) / 연수별: 직위·성명·이수확인(이수번호) |
| 계산 | 금액 = 수량 × 단가, 학급별 SUMIF로 사용액·잔액, 학년 합계 | 없음(눈으로 빈칸 찾기) |
| 운영 방식 | 안내문(학급 10만 원, 디지털 기기 불가, 쿠팡·아이스크림몰, 담당자 일괄 장바구니) + 마감일 | 연수마다 담당자가 다르고, 3년 주기 연수는 예전 이수번호 재입력 |
| 시트의 불편 | 학급 드롭다운 서식 깨짐(날짜로 표시), 남의 반 행 수정 가능, 금액 초과는 글자로만 표시 | 탭 14개를 오가며 내 이름 찾기, 누가 덜 했는지 한눈에 안 보임 |
| **티로드에서** | **여러 줄형**: 반마다 줄 추가, 금액·잔액 자동, 예산 넘으면 빨강, 학년별 예산 현황 자동, 내 반만 수정 가능 | **행렬형**: 받는 사람은 연수 14개를 한 화면에서 이수번호 붙여넣기/'해당 없음', 보내는 사람은 사람 × 연수 행렬, 연수별 이수율, 덜 마친 사람에게 "안 한 연수만" 적힌 독촉 문구 |

모으기의 형태는 이렇게 세 가지가 된다: **한 줄형**(반·사람마다 1줄, 기존), **여러 줄형**(준비물), **행렬형**(연수).

### 3-3. 외부 링크가 필요한가 — 모든 교사 로그인은 무리인가
- **무리인 것은 '로그인 화면'이지 '계정' 자체가 아니다.** 매번 아이디·비밀번호를 치게 하면 쪽지 링크 하나로 30초 만에 끝나는 경험이 깨지고, 받는 사람이 먼저 가치를 보는 바이럴 구조도 무너진다.
- 반대로 v1.1의 "로그인 없이 이름 고르기"는 **누구나 남의 이름을 고를 수 있다**는 구멍이 있다. 취합 정도는 괜찮아도 공지 확인, 수리요청, 업무분장 수정까지 가면 문제가 된다.
- **타협안(v1.2)**:
  1. 학교 구성원은 **티로드 안에서**. 처음 한 번 초대(쪽지) 링크 → 이름 선택 → **휴대폰 문자 인증 1회** → 그 PC를 1년 기억. 그다음부터는 쪽지 링크를 누르면 바로 내 칸이다(로그인 화면 없음). 학교 메일 인증은 초등 보유율이 낮아 보조 수단으로.
  2. **외부 링크는 옵션**: 명부에 없는 사람(방과후 강사, 첫날 기간제, 업체)용. 칸 하나 제출만 되고 다른 화면은 안 보이며, 마감되면 링크가 닫힌다. 모으기를 만들 때 '받는 방식'에서 켠다.
- 남은 판단: 문자 인증 비용(건당 약 10~20원, 연 1회 × 교직원 수)을 무료 플랜에서 부담할지.

## 4. 게시판 (구 '공지')
메뉴 이름을 **게시판**으로 바꾸고 탭 세 개로 나눴다: **공지 · 수리요청 · 양식 자료실**. 공지 기능(판 올림·diff·확인 필수)은 그대로다.

### 4-1. 수리요청 (시설 / 정보 필터)
- 요청: 분류(시설·정보) · 위치(기본 = 우리 반 교실) · 한 줄 내용 · 메모 · 사진 · 급함.
- 상태: 접수 → 방문 예정 → 처리 중 → 완료. 바뀔 때마다 요청한 선생님 🔔.
- 시설 = 행정실 시설 주무관(교직원 계정이라 권한 문제 없음).
- 정보 = **외부 유지보수 업체**.

### 4-2. 외부 업체 계정 — 간편하고 문제없이

| 방법 | 간편함 | 문제 |
|---|---|---|
| A. 공용 아이디·비밀번호를 업체에 줌 | 쉬움 | 담당자가 바뀌어도 이전 사람 접근이 남음, 비밀번호 돌려쓰기·유출 |
| B. 업체 직원을 교직원처럼 가입 | 보통 | 명부가 오염되고 일정·공지·명부가 다 보임 |
| C. 비밀 링크만 줌 | 아주 쉬움 | 링크가 새면 누구나 들어옴, 누가 처리했는지 기록 없음 |
| **D. 업체 계정 + 담당자 휴대폰 인증 (채택)** | 쉬움 | 아래 |

D안 동작:
1. **정보부장이 휴대폰 번호 하나로 초대**한다. 업체 담당자는 문자 인증으로 들어오고, 비밀번호는 없다.
2. **볼 수 있는 것은 '정보 수리요청' 게시판 하나**뿐이다. 일정·공지·명부·모으기는 메뉴 자체가 없다.
3. **요청자 이름 대신 위치만** 보인다(예: 4-2 교실). 교직원 개인정보가 업체로 넘어가지 않는다.
4. **사용 기간 = 계약 기간**(예: 학년도 말 2/28). 끝나면 자동으로 만료되고, 다음 해 재계약 때 초대 한 번이면 된다.
5. **담당자가 바뀌면 번호만 바꾼다.** 이전 사람의 접속은 즉시 끊긴다. 접속 기록은 남는다.
6. 업체 한 곳이 보통 지역 학교 여러 곳을 맡으므로 **한 계정으로 담당 학교 전부**를 한 화면에서 본다. 업체가 "다른 학교도 티로드 쓰면 편하다"고 말하게 되므로 **학교 간 확산 경로**가 하나 더 생긴다.

확인 필요: 교육청 정보보안 지침의 외부인 시스템 접근 규정, 유지보수 계약서의 개인정보 처리 위탁 조항.

### 4-3. 양식 자료실 — 고티처 양식 자료실과 동일
고티처 코드(`dev/goteacher` `g5_board_forms.sql`, `forms_import`)를 확인해 그대로 옮겼다.
- 분류 **학교(57)·교육청(22)**, 글 **79건** 같은 목록(제목·설명·"이렇게 쓰세요"·hwpx 첨부 1개)
- 목록: 분류 배지 · 제목 · 운영자 · 조회 · 날짜, 정렬(최신·조회·다운로드), 20건씩 페이지, 검색
- 보기: 설명 → 이렇게 쓰세요 → 한글(hwpx) 안내 → 첨부(파일명·크기·다운로드 수) → 이전·다음 글
- 권한: **운영자만 올림**, 보기·다운로드는 로그인 없이 누구나(검색 유입용 — 고티처와 같음)
