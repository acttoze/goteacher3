# 34. 구버전 고티처 운영 DB 분석 (2026-11-09)

구버전 goteacher.xyz의 운영 DB를 읽기 전용으로 조회해 정리했다. 개인정보(이름·메일·전화)는 집계만 했고 원문은 이 문서에 넣지 않았다. 이관 계획은 `35_db_migration_plan.md`.

## 1. 원천 시스템

| 항목 | 값 |
|---|---|
| 코드 | 맥 `~/moon/dev/goteacher`(그누보드5 + PHP 7.4, 테마 `ace`). 서버에서는 코드를 고치지 않는다 |
| 운영 | OCI `oci_tailscale`의 `/home/ubuntu/prod/goteacher_prod`, 컨테이너 `goteacher-prod`(Traefik `Host(goteacher.xyz)`) |
| DB | 공용 MySQL 컨테이너 `mysql`의 DB `goteacher`(개발용은 `goteacher_dev`), 계정 `goteacher`. 비밀번호는 서버의 `data/dbconfig.php`에만 있음 |
| 첨부 | `goteacher_prod/data/file/<bo_table>/` — 일정 `goteacher` 1.1GB, 게시판 `free_school` 280MB |
| 로그인 | 아이디·비밀번호(그누보드 PBKDF2: `sha256:12000:<salt>:<hash>`, 2,897명) + 학교 가입용 4자리 PIN(`school.pw`, 평문). 소셜 로그인은 꺼져 있음(`g5_member_social_profiles` 0행) |

> 주의: 구버전 저장소의 `docs2/03_DB_스키마.md`는 틀린 곳이 있다(mb_2·mb_5 의미, 달력 테이블 이름). 아래는 코드와 운영 데이터로 확인한 것이다.

- **사용자 채널**은 사실상 몇 곳만 쓴다: `학교마을협력과`(교육청 부서, 팀별 채널 5개·약 5,000건), 대전느리울초 "업무 및 행사" 1,148, 인천연수초 "특별실사용"·"학사일정", 인천금마초 "유치원행사". 채널은 가입 비밀번호가 있어 **구독자만 보는** 구조다(`mb_ch`에 `c<wr_id>`).
- **복무**(wr_4=2)는 99.8%가 `이름 | 내용` 형식인데, 내용이 `출장(08:30~16:30,가수원초,순회학교 근무)`, `병가(시간강사)`처럼 **사유가 섞인 자유 글**이다. 새 버전은 "유형·시간만" 받는다(3라운드 결정).
- **반복·종일/시간 구분 없음.** 모든 일정이 날짜 범위다.
- **중복**: "다른 채널로 복사"가 행을 통째로 복제해서 (학교·작성자·날짜·제목)이 같은 묶음이 749개 있다.
- **2026학년도 일정 12,834건**(봇 제외) 중 본문 있음 3,672 · 첨부 있음 149(191개 파일, 177MB) · 댓글 달린 것 25 · 공지 5 · 완료 4.
- 관련 테이블: `g5_read_log`(일정 읽음 기록 32k), `g5_scrap`(일정 즐겨찾기 39), `g5_srd_pushmsg`(알림 1.8k), `g5_neis_academic_override`(NEIS 행 수정·숨김 7) — 이관 가치 낮음.

## 9. 조회 방법(재현)

서버 안에서만 비밀번호를 읽고 출력하지 않는다. 읽기 전용 SELECT만 썼다.

```bash
B=$(printf '%s' "SELECT COUNT(*) FROM g5_member" | base64)
ssh oci_tailscale "B=$B bash -s" <<'R'
PW=$(sed -nE "s/.*G5_MYSQL_PASSWORD',\s*'([^']*)'.*/\1/p" /home/ubuntu/prod/goteacher_prod/data/dbconfig.php)
echo "$B" | base64 -d | docker exec -i -e MYSQL_PWD="$PW" mysql mysql -ugoteacher goteacher --default-character-set=utf8mb4 --table
R
```
