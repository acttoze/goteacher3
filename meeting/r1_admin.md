# R1 제안서 — 교무부장(보내는 쪽) 관점

## 1. 연간 사이클과 폭발 지점
- **2월**: 업무분장표, 학사일정, 시간표, 담임 배정, 교실·특별실 배정. 1년 치 뼈대가 이때 정해진다. 온보딩 적기는 3월이 아니라 2월 셋째 주다.
- **3월**: 기초조사, 각종 희망조사(방과후·돌봄), 연간계획 제출, 학부모총회. 취합 공문이 가장 몰리는 달이다.
- **학기중**: 주간교육계획은 매주 목·금 확정해서 배포한다. 출장·조퇴가 생기면 그날그날 보결을 짜야 하고, 현장체험학습·평가·연수이수 실적도 취합한다.
- **7·12월**: 성적 마감, 생기부 점검, 연수이수 보고, 다음 학기 계획을 한꺼번에 처리한다.
- **방학**: 사람이 거의 없다. 대신 이 시기에 차년도 업무분장 초안을 미리 손본다.

## 2. 보내는 쪽의 실제 고충
- 주간계획 hwp를 쪽지로 뿌린 뒤 "3교시 → 4교시 변경"이 생기면 재발송 v2, v3가 나간다. 어느 판이 최신인지 아무도 모른다.
- 취합할 때 미제출자를 명단과 직접 대조해 개별 쪽지로 독촉한다. 하루가 이렇게 날아간다.
- 보결은 출장자 시간표와 빈 교사 시간표를 교감이 머릿속으로 맞춰 짠다.
- 공문은 에듀파인에서 분배한 뒤로 처리 여부가 보이지 않는다. 마감 직전에 "그거 누구 거였죠?"가 나온다.

## 3. 필요한 학교 고유 데이터 구조
교시(1~7, 중간놀이·점심), 학년·반, 부서·업무분장(사람↔업무 매핑, 해마다 갱신), 장소(특별실 예약·중복 경고), 대상(전교·학년·희망자·교직원), 참석자·인솔자, 복무유형(출장·조퇴·외출·연가·병가), 결재 여부(나이스 상신 완료 체크), 마감일·제출 상태.
DB를 보면 제목의 14%가 `이름|출장(시간, 장소)` 형식이다. 이 정보를 필드로 받아야 보결표와 월중행사표가 자동으로 나온다.

## 4. 법·보안 주의점과 현실적인 우회책
- **학생 개인정보**: 학생 이름·연락처는 저장하지 않는다. 다루는 대상은 교직원 업무 데이터로 한정한다(교직원 업무 협업 도구 포지션).
- **공문 원문**: 원문 파일은 받지 않는다. 문서번호·제목·담당자·기한 같은 메타데이터만 입력받고 원문은 에듀파인 링크로 연결한다.
- **클라우드**: 교육청 화이트리스트와 클라우드 보안인증(CSAP)을 확인해야 한다. 학교 차원에서는 '교내망 차단 여부' 체크리스트를 미리 제공한다.
- **나이스**: 복무 결재는 나이스에서만 할 수 있어 연계가 불가능하다. 그래서 티로드는 "일정 공유 + 나이스 상신했음" 체크로 끝낸다. 학사·급식은 공개 API로 자동으로 채운다.

## 5. 교감·교장이 예산을 쓸 이유
1. **보결·복무 현황판**: 오늘 누가 비고 누가 들어가는지가 교감의 아침 업무를 30분 줄인다.
2. **공문·취합 처리 추적**: 마감 누락이 줄어 교육청 독촉 전화가 감소한다. 기관 평가에도 쓸 수 있다.
3. **인수인계 자산화**: 업무분장과 1년 치 일정이 남아 다음 해 담당자에게 넘어간다. 잦은 전보에 대한 보험이다.

**중·고등학교에서 달라지는 점**: 교과교실제 때문에 시간표가 교사 단위로 돌아가고 보결·자습감독 수요가 초등의 몇 배다. 교무·학년부가 이원화되어 있고, 고교학점제로 선택과목 수강신청과 고사(시험) 감독 배정이 핵심 업무다. 그래서 중·고 진입로는 "시험감독표·보결표 자동 생성"이 되어야 한다.
