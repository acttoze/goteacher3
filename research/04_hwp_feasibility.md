# 04. 한글(HWP/HWPX) 취합 기술 타당성 — 실측 결과

- 실험일: 2026-10-28
- 환경: macOS, 한컴오피스 없음, Java 없음
- 재료: 고티처 양식 아카이브 1,376개(hwp 1,136 / hwpx 240) 전체 + 취합형 키워드(명단·현황·조사·신청·이수 등) 101개
- POC 코드: `research/hwp_poc/` (실행법은 README)

## 1. 결론

**한글 앱 없이 서버에서 "표 찾기 → 칸 채우기 → 원본 서식 유지 저장"이 된다.** 공개 라이브러리 python-hwpx 6.10(Apache-2.0)으로 HWPX와 HWP 5.0 모두 읽고, 표 칸만 고쳐 다시 저장할 수 있다. 남은 위험은 두 가지다.

- 자동으로 고른 표·칸이 틀릴 수 있어 사람이 확인해야 한다.
- **실제 한글 프로그램에서 열리는지는 아직 확인하지 못했다.**

| 공정 | 판정 | 근거 한 줄 |
|---|---|---|
| 1. 표만 찾아내기 | **가능** | 읽기 성공 1,376/1,376. 표 개수는 독립 파서 3종이 모두 일치. |
| 1-b. 여러 표 중 취합용 표 고르기 | **조건부** | 자동 1순위가 맞은 경우는 눈 검토 16건 중 11건(약 70%). 문서의 72%는 후보가 2개 이상이다. 사람이 미리보기에서 눌러 확정하는 UX가 필요하다. |
| 2. 표 구조 해석 → 웹 입력 칸 | **조건부** | 병합 셀·머리글 행·행 머리(반·번호)·합계 행·단위 칸("명")은 자동으로 읽힌다. 단 "□예 □아니오", "(  )", "직위：" 같은 글자 사이 빈칸은 MVP 범위 밖이다(문서의 10~14%). |
| 3. 각자 자기 행/칸 제출 → 서버 병합 | **가능** | 형식과 무관한 일반 웹 기능이다. 칸 주소 (표, 행, 열) 단위로 병합하고 충돌을 검출하는 것을 POC로 확인했다. |
| 4. 원본 파일의 그 표 그 칸에 다시 넣어 저장 | **가능**(HWPX) / **조건부**(HWP) | HWPX는 266/266 문서에서 값·구조·다른 칸·다른 파트가 모두 그대로였다. 바뀐 것은 해당 섹션 XML 하나뿐이다. HWP→HWP 재저장은 78/78 성공했고, 독립 렌더러 rhwp에서도 모두 열렸다. 단 HWP는 파일 전체를 새로 쓰는 방식이다. |
| 5. 내려받아 한글에서 열기 | **조건부(미검증)** | 독립 구현 2종(rhwp, olefile 레코드 파서)과 렌더링 이미지로는 정상이다. **한컴 한글 실기 확인은 아직 못 했다.** 출시 전 확인이 필수다(4장 체크리스트). |

**HWP 열 표에 대한 보충**

- **3건 제외 이유:** 1,136개 중 3개는 확장자만 `.hwp`이고 실제로는 HWPX(zip)였다. 그래서 위 HWP 열의 분모는 1,133이다. 확장자 대신 파일 첫 바이트로 형식을 판별하면 이 3건도 정상으로 열린다.
- **표 개수 교차 일치:** 처음에는 1건(표 49개 중 7개)이 어긋나 보였다. 확인해 보니 그 7개는 바탕쪽(masterpage)에 들어 있었고, 실제로는 100% 일치했다.
- **변환 손실 보고:** python-hwpx는 변환하지 못한 요소를 보고서에 남긴다. 해당 문서는 118건이다.
  - 범위 태그(range-tag) 90건
  - 라벨 문서 항목 32건
  - 표 이름 4건
  - 변경 추적 2건
  - 이번 실험에서 이 요소들 때문에 표 칸 값이 틀린 경우는 없었다.

**표에 대한 보충**

- **더미 값 형식:** "값N" 꼴이고, 단위 칸이면 뒤에 "명" 같은 단위를 붙였다.

### 2-3. 직접 XML 조작과 라이브러리 비교 (HWPX)

| | python-hwpx `table_patch.fill_cells` | 자체 lxml 조작 (`fill_own`) |
|---|---|---|
| 정확도 | 266/266 | 266/266 |
| 원본 보존 | 바이트 보존. 섹션 안에서도 고친 문단만 바뀌고 XML 선언·따옴표·네임스페이스 모양은 그대로다. | 섹션 XML 전체를 다시 직렬화한다. 의미는 같지만 XML 선언 따옴표 같은 모양이 바뀐다. |
| 안전장치 | 개체가 든 칸 거부, 병합 영역 중복 채우기 거부, SQUEEZE 줄바꿈 해제, 칸 폭에 맞춰 글자 줄이기(옵션), open_safety 검사 | 직접 구현해야 한다. |

**선택:** python-hwpx를 쓰고, 자체 lxml 경로는 라이브러리 장애에 대비한 예비로 둔다. 다시 압축할 때는 아래 조건을 지킨다. 두 경로 모두 지키도록 구현했다.

- mimetype을 첫 항목에 무압축(STORED)으로 둔다.
- 원본의 항목 순서와 압축 방식을 그대로 따른다.
- 고친 문단의 `linesegarray`(줄 배치 캐시)는 지워서 한글이 다시 배치하게 한다.

### 2-4. HWP(바이너리) 쓰기 경로

| 경로 | 이 환경에서 실행 | 결과 |
|---|---|---|
| **python-hwpx**: HWP5 읽기 → HWPX 모델 → 칸 채우기 → `write_hwp5` | 됨 | 78/78 성공. 행 추가(명단 초과 인원) 후 채우기도 HWP→HWP로 성공했다(`examples/`). |
| **rhwp**(@rhwp/core 0.8.7, Rust+WASM, MIT): 원본을 직접 열어 `insertTextInCell` → `exportHwp` | 됨(node, 브라우저도 가능) | 2개 문서에서 40칸, 76칸 성공. 레코드 파서와 python-hwpx 재읽기로 값을 확인했다. 표본이 작아 예비 경로로 둔다. |
| hwplib / hwpxlib (Java, Apache-2.0) | **안 됨**(Java 없음) | HWP 쓰기를 지원한다고 알려져 있다. 미실험. |
| LibreOffice + H2Orestart | 안 됨(LibreOffice 미설치) | H2Orestart 저장은 ODT만 된다고 한다. HWP/HWPX를 돌려주는 경로가 아니어서 제외했다. 미실험. |
| 한컴 HWP SDK, 통합문서뷰어(DocsConverter), 웹한글 기안기, 한글 오토메이션 | 상용·미실험 | 가격 비공개(구매 문의). 오토메이션은 Windows와 한글 설치가 필요하다. 5장 출처 참고. |

**"hwp로 올렸는데 hwpx로 돌려줘도 되나"에 대한 판단**

- 근거 1: 한컴은 2021년 4월 한글 2014 VP 이상에 hwpx 기본 저장 옵션을 배포했다.
- 근거 2: 2026년 4월 정부 발표에 따르면 중앙부처는 2022년부터 hwpx가 의무다. 온나라는 5월, 공직자 메일은 10월부터 hwp 첨부를 제한한다.
- 따라서 hwpx 반환은 대세와 맞는다. 다만 학교 PC의 구버전 한글(2014 VP 미만)에서는 깨질 수 있다. 교육청·K-에듀파인 쪽 hwpx 정책 자료는 찾지 못했다.
- **권장:**
  - 기본은 "올린 형식 그대로 반환"(hwp→hwp)으로 하고, hwpx 파일도 같이 준다.
  - 한글 실기 검증에서 HWP 쓰기가 불안하면 hwpx 반환으로 기본값을 바꾼다.
  - 이 전환은 설정 한 줄로 된다.

### 2-5. 눈으로 확인하는 방법(한글 앱 없이)

- 방법: rhwp(WASM)로 쪽별 SVG를 만들고 Chrome 헤드리스로 PNG를 찍는다(`render.mjs`, `svg2png.sh`).
- 결과: 원본·결과 344개 파일(lib.hwpx 266, lib.hwp 78)과 왕복본 78개가 모두 열리고 렌더됐다. 병합·글꼴 차이·테두리가 원본처럼 보이는 것을 이미지로 확인했다(`examples/*.png`).
- 한계: 한컴 엔진이 아니고 글자 폭을 근사치로 잰다. 줄바꿈·쪽 나눔은 실제와 다를 수 있으므로 **최종 판정은 한글에서 해야 한다.**
- 서비스 활용: 같은 렌더러를 브라우저 미리보기와 표 선택 UI에 쓸 수 있다. rhwp는 셀 좌표(`getTableCellBboxes`)도 준다.

```
[브라우저]  업로드 → rhwp(WASM) 미리보기 → 교사가 표 클릭으로 확정·칸 라벨 수정 → 입력 폼(행 배정)
                                    ↑ 표·칸 좌표                        ↓ 제출(JSON: 표·행·열·값)
[서버 Python] python-hwpx: load/convert → analyze/schema → (병합) → fill_cells(+행 추가) → hwpx 저장 → write_hwp5(hwp 원본이면)
              ㄴ 작업 큐(문서당 최대 수십 초) · 원본/결과 파일 보관 · 결과 재검증(verify)
```

- **서버**
  - Python 3.10 이상, python-hwpx 6.10 버전 고정(Apache-2.0), lxml.
  - 업로드 처리와 문서 생성은 큐 작업(RQ나 Celery 등)으로 돌리고 시간 제한을 둔다.
  - 신뢰할 수 없는 파일이므로 다음을 지킨다.
    - lxml 엔티티 해석을 끈다.
    - python-hwpx의 zip 폭탄 가드를 쓴다.
    - 작업마다 메모리와 시간을 제한한다.
- **HWP 처리**
  - 확장자가 아니라 매직 바이트로 판별한다(`PK`면 hwpx, `D0CF11E0`이면 hwp).
  - hwp는 HWPX로 변환해 같은 파이프라인을 탄다. 저장할 때 HWP로 되돌리고 HWPX도 같이 준다.
  - 변환 보고(unconverted/dropped)에 항목이 있으면 사용자에게 "일부 서식 정보가 바뀔 수 있음"을 알린다.
- **프로토타입(GitHub Pages)**
  - rhwp만으로 브라우저 안에서 열기, 미리보기, 칸 채우기, HWP/HWPX 저장까지 할 수 있다.
  - 서버 없이 시연이 가능하다. 단 rhwp는 0.8.x 초기 단계라 운영 경로로는 python-hwpx를 권장한다.
- **pyhwp는 쓰지 않는다:** AGPL-3.0이라 SaaS 코드에 넣지 않는다. 검증용으로만 썼다.
- **사람이 확인해야 할 부분(UX)**
  1. **표 선택**: 후보를 점수 순으로 미리보기 위에 강조한다. 문서의 72%가 후보 2개 이상이고, 1순위 정답률은 약 70%다. 반드시 한 번 눌러 확정하게 한다.
  2. **입력 칸 확인**: 자동 라벨(예: "1반 / 4학년 #2")을 다듬는다. 칸을 켜거나 끄고, 합계 행은 자동 합계·제외로, 단위 칸은 "숫자+명"으로 둔다.
  3. **칸 배정**: 행 머리(반·이름)별로 담당자를 지정한다. 명단형은 "다음 빈 행에 추가"로 받고, 모자라면 행을 추가한다(POC 검증됨).
  4. **충돌**: 같은 칸에 다른 사람이 덮어쓰면 경고한다. 칸마다 최근 작성자를 기록한다.
  5. **넘침 경고**: 저장 전에 렌더해서 쪽수가 바뀌는지 본다. 바뀌면 경고하고 "글자 줄이기" 옵션을 준다(python-hwpx `fit_max_lines`).
  6. **최종 확인**: 결과 파일을 한글에서 연다. 출시 전에는 아래 체크리스트로 확인한다.

### 출시 전 한글 실기 체크리스트

- 대상: 각 경로 대표 10건(`examples/` 포함)
- 확인할 버전: 한글 2014 VP, 2018, 2020 이상
- 확인 항목
  - ① 오류 없이 열린다.
  - ② 값이 정확한 칸에 들어가 있다.
  - ③ 병합·테두리·글꼴·쪽 구성이 원본과 같다.
  - ④ 다시 저장했다가 다시 열 수 있다.
  - ⑤ hwp 결과는 "문서 복구" 경고가 뜨지 않는다.
- 우선 확인할 파일: pyhwp가 못 연 왕복 HWP 1건(2026 인사자문위원회 구성 명단)

## 4. MVP(이번 겨울)와 v1, 리스크와 비용

**MVP에 넣을 것**

- hwp와 hwpx 업로드(매직 바이트 판별)
- 표 후보 미리보기와 사람의 확정
- 순수 빈 칸과 단위 칸 입력
- 세 가지 수집 방식
  - 행 머리 배정형(반별 행)
  - 명단형(빈 행 순서대로 채우고, 모자라면 행 추가)
  - 단건 신청서형(kv)
- 병합과 충돌 경고
- 결과는 원본 형식과 hwpx 동시 제공, 렌더 미리보기 포함
- 합계 행은 입력에서 제외한다(자동 합계는 시간이 되면 넣는다).

**v1로 미룰 것**

- 체크박스(□→■), "(  )"·"라벨：" 사이에 끼워 넣기, 날짜 자리, 서명 이미지
- 한 양식에서 여러 표를 동시에 취합하기
- 중첩 표 안쪽 표를 정밀하게 다루기
- 합계 자동 계산
- 1인 1부 신청서 여러 장을 한 파일로 묶기
- 역방향 취합: 이미 작성돼 돌아온 hwp 여러 개에서 표 값을 뽑아 엑셀이나 한 표로 모으기. 읽기 성공률 100%라 기술 위험은 낮다.

**리스크**

| 리스크 | 수준 | 대응 |
|---|---|---|
| 한글 실기 미검증: 특히 python-hwpx가 새로 쓴 HWP 바이너리 | **높음(미확인)** | 출시 전 체크리스트를 돌린다. 실패하면 hwpx 반환을 기본으로 바꾸고 rhwp 직접 편집 경로를 쓴다. 그래도 안 되면 그때 한컴 SDK 견적을 받는다. |
| 표·칸 자동 판단 오류(약 30%) | 중간 | 사람 확정 UX로 해결한다. 자동은 추천만 한다. |
| 라이브러리 성숙도: python-hwpx 6.x는 업데이트가 빠르고, rhwp는 0.8.x | 중간 | 버전 고정, 회귀 테스트(이번 벤치 스크립트 재사용), 자체 lxml 예비 경로 |
| 값이 길어 행·쪽이 늘어남 | 낮음~중간 | 렌더해서 쪽수를 비교하고, 경고와 글자 줄이기 옵션을 준다. |
| 큰 문서 처리 시간(최대 19초) | 낮음 | 큐 처리하고 진행률을 표시한다. |
| 업로드 양식 속 개인정보(명단 등) | 중간 | 보관 기간 정책과 자동 삭제, 암호화 저장 |
| 공개 규격 이용 문구 | 낮음 | 서비스 화면이나 약관에 다음 문구를 넣는다. "본 제품은 한글과컴퓨터의 한글 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다." |

**비용**

- MVP에 상용 SDK는 필요 없다.
- 오픈소스 라이선스는 Apache-2.0(python-hwpx)과 MIT(rhwp)다.
- 한컴 HWP SDK·변환 솔루션은 가격이 공개되지 않아 견적 문의가 필요하다. 한글 실기 검증에서 오픈소스 결과물이 거부될 때만 검토한다.
